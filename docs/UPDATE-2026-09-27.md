# 2026-09-27 更新说明

本次更新修复批量生成、长任务恢复和任务控制链路，并改进批量执行状态展示。沿用 Python、SQLite、ComfyUI 和 React/Tauri，不要求重置数据库。

## 批量生成与调度

- 将批量编排推进拆为持久化步骤：分镜、素材规划、图片提示词、图片任务、视频提示词和执行 DAG 登记。等待子任务时释放编排执行槽。
- 图片任务及时加入所属批次，动态编排期间不提前判定批次完成。
- 调度按真实依赖与资源条件领取任务，隔离单个项目失败，避免不可执行分支阻塞其他项目。
- 失败启动及创建回包丢失后复用草稿批次，提供草稿启动入口。

## 执行恢复与任务控制

- 增加执行尝试、租约、提交意图、外部任务对账和迟到结果隔离；不把租约过期当作 GPU 已停止。
- 统一暂停、恢复、取消、重试和批量命令作用范围，保存幂等回执。
- 暂停停止新派发；取消等待执行端确认。未知外部结果先对账，不盲目重新提交。
- 修复任务列表操作受辅助查询失败或刷新挂起影响的问题，增加请求超时和断线状态保留。
- 普通失败重试保留次数和截止时间预算。预算用尽、无外部提交且明确本地失败的批量编排可选择“重试编排（新执行）”：创建新任务、替换批次成员，保留原失败记录和预算。
- 修复产物收集失败时重试入口被错误隐藏的问题；收集重试观察原外部任务，不重新生成。

## LLM 与界面

- 为语义操作加入调用预算、上下文限制和确定性校验，复用已确认内容，减少恢复时的重复生成。
- 保留项目审核策略，避免批量启动隐式改变审核选择。
- 批量页展示当前具体环节及图片、条件编码、H3 扩散、后处理/交付的完成数量。
- 编排检查点携带素材或片段范围；尚未确定总量时展示已登记数量，不显示精确百分比。
- 统一任务状态、错误诊断、等待原因和操作入口，区分重试失败、恢复派发和新执行。

## 使用与升级

更新源码后需重新加载后端及前端才能使用新逻辑。先停止新派发并备份控制数据库；保留媒体和外部任务关联，不清空数据库。

若失败详情提示缺少工作流、模型或输入，先修复配置再重试。本次发现的失败编排已达到 3/3 次尝试，原因是 DAG 编译预检缺少工作流配置；新执行入口不会自动修复这些配置。

本次仅交付源码与更新说明，不发布安装包，不升级 ComfyUI 节点或模型。
