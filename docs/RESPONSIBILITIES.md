# 职责与协作

## 1. 决策原则

- 用户拥有产品目标、范围、成本和审美的最终决定权。
- 主智能体拥有技术整合权，维护架构、接口、任务依赖和仓库一致性。
- 子智能体领取边界明确、可独立验收的模块任务。
- 核心 Schema 和跨模块接口由主智能体先冻结，再开始并行实现。
- 多个子智能体不得同时修改同一核心模型或迁移文件。
- 每项工作必须有交付物、验收命令或可观察结果，不能只以“代码已写”结束。

## 2. 用户职责

用户担任产品负责人和最终验收人：

- 决定 MVP 范围及冲突需求的优先级。
- 提供可运行的 H3、ComfyUI、模型、工作流和节点版本信息。
- 提供公共角色图、场景/风格图及其他合法测试素材。
- 确定约 60 秒的固定验收样片。
- 审核大纲、电影分镜、片段衔接和最终视觉效果。
- 决定图片生成、音频、桌面封装和操作系统支持边界。
- 提供必要的 API 凭据并只保存在本机安全配置中，不提交仓库。
- 批准会产生明显费用、长时间占用 GPU 或改变产品范围的操作。

用户不负责日常代码合并、Schema 冲突或任务调度实现。

## 3. 主智能体职责

主智能体担任技术负责人和集成维护者：

- 维护项目计划、架构决策、领域 Schema 和 API 契约。
- 把用户目标拆为有依赖关系的可验收任务。
- 在分派实现前冻结核心接口，避免重叠改动。
- 分派子智能体，审查交付，处理跨模块问题并完成最终合并。
- 维护数据库迁移、兼容性策略、许可证记录和仓库质量门。
- 运行端到端验收、故障恢复测试和回归测试。
- 向用户报告进度、风险、需要裁决的产品问题和实际验证结果。
- 阻止 LLM 绕过校验、审核、预算或高成本任务确认。

主智能体不能代替用户作审美批准，也不能自行扩大 MVP。

## 4. 子智能体职责

| 模块 | 主要交付 | 关键验收 |
| --- | --- | --- |
| H3/ComfyUI 适配 | 节点探测、提交、进度、取消、历史恢复、Motion Context 串联 | 两段连续生成及重启恢复 |
| 领域模型 | Schema、不可变修订、依赖边、迁移 | 引用、版本、失效传播测试 |
| LLM Harness | 操作协议、提示模板、Schema 输出、局部修复、锁定字段 | 错误输出被拦截，锁定内容不漂移 |
| 调度与产物 | 状态机、持久化队列、指纹、文件存储、血缘 | 重复提交去重，失败后局部恢复 |
| 素材系统 | 公共/专用素材、用途绑定、版本与预览 | 主角参考进入所有相关片段 |
| UI 工作台 | 大纲、分镜、素材、队列和审核交互 | 无需手改数据库完成一次闭环 |
| 导出 | FFmpeg 拼接、转码、媒体探测 | 生成标准 H.264/AAC MP4 |
| 平台与测试 | Windows/Ubuntu 脚本、测试、诊断文档 | 干净环境安装及故障用例通过 |

子智能体必须在开工前复述输入、输出、允许改动目录和验收标准；不得擅自改变共享 Schema。交付时列出修改文件、验证结果、已知限制和风险，并保留用户及其他智能体已有改动。

## 5. 首轮实际分工

### 用户

在 P0 开始前提供或确认：

1. 当前可运行的 ComfyUI 目录、版本和启动方式。
2. H3 模型及相关自定义节点的确切版本。
3. 一个短片段素材包和一组公共主角多图参考。
4. 一个需要连续两段以上生成的长镜头描述。
5. 本文末尾产品决策清单中的选择。

### 主智能体

1. 完成本轮规划文档并维护决策记录。
2. 建立 P0 验证脚手架和最小领域 Schema。
3. 冻结 ChainSpec、Worker Adapter、任务事件和产物 manifest。
4. 根据验证结果给子智能体划定目录和接口。
5. 集成各模块并向用户演示第一条连续生成链。

### 子智能体

首轮调研已按产品边界、H3 执行层、LLM Harness 和任务系统完成。实现阶段按依赖顺序启动：

1. H3 执行：fork Motion Director，验证唯一 patch owner、帧预算和 Motion Context 的真实输入输出。
2. 领域/任务：依据冻结 Schema 实现数据库、状态机、产物和恢复。
3. LLM：依据冻结操作协议实现结构化生成、校验和局部修复。
4. UI、素材、导出、平台：待前三项接口稳定后并行。

## 6. 交付与验收流程

```text
用户确认目标与样片
-> 主智能体冻结任务接口和验收标准
-> 子智能体在独立模块实现并自测
-> 主智能体审查、集成和运行跨模块测试
-> 用户进行产品与审美验收
-> 主智能体记录结论并进入下一里程碑
```

代码完成要求：格式化、静态检查和自动测试通过；有可复现验收路径；数据迁移、恢复和失败行为有说明；不提交密钥、大型模型、生成缓存或来源不明素材；用户可见行为已验收或明确标记等待验收。

## 7. 需要用户确认的决策

以下推荐项可直接作为默认选择：

1. 产品形态：首版本地 Web UI，之后再用 Tauri 封装。
2. 上游策略：应用层独立，fork Motion Director 作为唯一 H3 Worker 执行引擎。
3. LLM 接口：OpenAI-compatible，首版只指定一个验收模型。
4. 图片来源：支持上传，并只接入一个固定图片生成 workflow；也可 P0 先只上传。
5. 音频范围：保留 H3 原生音频并允许导入一条外部音轨，TTS/字幕/BGM 延后。
6. 片段策略：默认目标 12 秒、硬上限 15 秒，实际净时长由 context 帧预算计算；允许覆盖拆分点。
7. 平台优先级：Windows 提供完整 UI，Ubuntu 优先作为 Worker 环境。
8. 后台行为：关闭浏览器页面不停止任务；显式停止控制平面时暂停任务。

没有得到确认前，P0 可以按推荐项验证，但不会把未确认扩展做成不可逆约束。
