# 项目计划

## 1. 产品目标

首版服务已经使用或愿意部署 ComfyUI 的个人创作者和小型工作室，主要制作 30 秒至 3 分钟的剧情短片、概念预告和广告视频。

产品要解决的不是“自动写提示词”，而是建立一个可编辑、可审核、可恢复、可追溯的生产流程：

```text
创建项目
-> 输入创意与基础参数
-> LLM 起草结构化大纲
-> 用户审核大纲
-> LLM 起草电影分镜
-> 用户审核分镜
-> 管理公共素材和镜头素材
-> 编译为 <= 15 秒的 H3 生成片段
-> 通过 ComfyUI 生成并串联长镜头
-> 用户审核、局部修改或重试
-> 拼接并导出 MP4
```

## 2. MVP 边界

### 必须完成

- 单用户、单机、本地优先。
- 一套经过验证的 MiniMax H3 ComfyUI 工作流。
- 一种 OpenAI-compatible LLM 接入方式，并用一个实际模型验收。
- 大纲、电影分镜、H3 生成片段三层结构化数据。
- 公共参考素材、镜头专用素材及明确的用途绑定。
- 单段不超过 15 秒；长镜头自动拆分并通过 Motion Context 连续生成。
- 大纲、分镜、生成结果三个正式审核门。
- 持久化队列、取消、失败重试、局部重跑和应用重启恢复。
- 提示词、参数、模型输出、素材和依赖关系的版本记录。
- 基础拼接、统一转码和 H.264/AAC MP4 导出。
- Windows 开发环境跑通；Ubuntu 至少验证 Worker/ComfyUI 路径。

### 暂不纳入

- 多用户、在线协作、账号权限和商业计费。
- 完整非线性剪辑器、专业调色和复杂特效。
- 多视频模型适配、模型或节点市场。
- 自动口型、多角色 TTS、智能配乐和复杂字幕系统。
- 自建云算力平台和复杂分布式调度。
- AI 无限自动重试或未经用户许可自动消耗高成本资源。
- 移动端。

## 3. 阶段与验收

### P0：关键技术验证

目标：在写完整产品前消除 H3 执行层的关键风险。

- fork 并固定 Motion Director、官方 H3 节点和 ComfyUI 的 commit。
- Worker 冷启动时只允许一个 Motion Context runtime patch owner。
- 通过 API 提交 H3 任务，读取进度、历史和结果。
- 验证 14 秒、16 秒和 31 秒电影镜头的拆分与成片时长。
- 分别测试 5、22、39 帧 context，确定继承帧是否占用 H3 的 15 秒预算。
- 验证公共多图参考会进入每个相关片段，局部素材只影响指定片段。
- 验证“批量条件预编码 -> 持久化缓存 -> 卸载编码器 -> 加载扩散模型 -> 连续生成”的显存与耗时收益。
- 对比逐片段换模与批量预编码两种路径，记录模型加载次数、总墙钟时间、峰值显存和缓存体积；稳定批次正常执行时编码器与扩散模型各最多加载一次。
- 验证 prompt、参考素材或编码器版本变化时只重编码受影响片段，缓存不发生跨项目或跨版本误命中。
- 验证 Visual+Audio、仅 Visual、仅 Audio、完全断开四种边界。
- 验证 Motion Context 缓存、局部重跑、失效传播和强制重启恢复。
- 比较 2、5、10 段长链的人物、动作、色彩和音质退化。
- 冻结首版 ChainSpec、Worker API、核心 Schema 和产物 manifest。

第一版同一 ComfyUI 实例不并装独立 `ComfyUI-H3-Motion-Context` 或 `Contex Loop`。它们与 Motion Director 的运行时补丁或多段编排职责重叠，只能在隔离实例中做备选验证。

退出条件：无需手工改数据库即可重复运行同一测试，重启控制程序和 ComfyUI 后能重新关联任务；成片时长误差不超过 1 视频帧，音画差不超过 1 视频帧。

### P1：手动纵向闭环

目标：先证明确定性系统可靠，暂不依赖 LLM 生成内容。

- 建立项目、导入公共素材并人工填写结构化分镜。
- 自动把长镜头编译为 H3 片段链。
- 查看任务状态、失败原因和生成结果。
- 只重跑指定片段及确实依赖它的后继片段。
- 重启后项目、任务、审核和产物均不丢失。
- 导出可正常播放的 MP4。

### P2：LLM 创作层

目标：让 LLM 在受约束的结构化接口内参与创作。

- 从创意生成符合 Schema 的大纲和电影分镜。
- 支持用户修改、锁定和只重新生成指定范围。
- 自动建议素材需求、动作、运镜和目标时长。
- 根据语义拆分长镜头，而不是机械平均切割。
- 自动编译 H3 提示词和素材绑定。
- 校验失败时进行最多 2 至 3 次局部修复，仍失败则交由人工处理。
- LLM 不得覆盖已批准内容或用户锁定字段。

### P3：MVP 产品化

目标：完成真实作品验收和可维护交付。

- 完成审核门、不可变修订、局部失效和回退。
- 取消、重试、缓存、日志和异常恢复行为一致。
- 项目能够备份和恢复。
- 提供 Windows 与 Ubuntu 的安装、运行和故障排查文档。
- 用固定的约 60 秒样片完成端到端回归验收。

### P4：后续能力

按实际需求评估图片生成、TTS、字幕、BGM、云端 Worker、多模型适配、自动接缝检测、桌面封装和更完整的时间轴。

## 4. 固定验收样片

用户需要提供一个约 60 秒的真实项目，至少包含：

- 1 个公共主角参考素材。
- 1 个公共场景或风格参考素材。
- 4 个电影分镜。
- 1 个超过 15 秒的连续镜头。
- 6 个或更多实际 H3 生成片段。

验收检查：

- 每个片段携带正确的公共和专用参考素材。
- 超长镜头在合理动作节点拆分，并正确传递 Motion Context。
- 中间片段失败后能从该处恢复。
- 修改或重生成一个片段只使真实依赖项失效。
- 应用重启后任务、审核、版本和产物仍然一致。
- 最终文件可由常见播放器正常播放。
- 人工审核未发现明显身份突变、动作跳变、黑帧、闪烁或音画断裂。

“无损衔接”不作为无法量化的验收词，使用上述可观察标准代替。

## 5. 当前里程碑

当前只启动 P0。进入实现前依次冻结：

1. H3 工作流、节点版本与唯一 patch owner。
2. 条件预编码格式、缓存指纹、模型驻留与卸载策略。
3. 核心领域 Schema 和数据库迁移规则。
4. ChainSpec、Worker Adapter、任务事件和产物 manifest。
5. LLM 操作类型、输入输出 Schema 和锁定规则。
6. UI 所依赖的 API 契约。

任何阶段都以可运行、可复现的纵向闭环为交付单位，不按页面数量或代码量判断完成度。
